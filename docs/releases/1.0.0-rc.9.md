# Stim 1.0.0-rc.9 - cache correctness and clearer run reporting

## Fixes

- Android builds are re-fingerprinted after Gradle succeeds, so inputs changed
  by Gradle or autolinking store the artifact, `lastBuild`, and JSON cache
  identity only under the post-build key. If re-fingerprinting fails, Stim
  installs the APK without caching it or reporting a stale cache identity
  ([2b689ad](https://github.com/appandflow/stim/commit/2b689ad)).
- Dev-client launches carry Expo's session-only `disableFab=1` parameter on
  iOS and Android. Expo versions that support the parameter hide the floating
  Tools button without changing the user's persistent preferences; older
  versions ignore it
  ([7c4dd23](https://github.com/appandflow/stim/commit/7c4dd23)).
- `stim android --json` includes `durationMs`, matching the documented iOS
  payload and reporting the wall time of the complete successful native run
  ([adc927e](https://github.com/appandflow/stim/commit/adc927e)).
- A warm iOS run reports the installed-app identity proof separately from
  Expo dev-client preference preparation, so a slow simulator command is
  attributed to the step that actually ran
  ([e858950](https://github.com/appandflow/stim/commit/e858950)).
