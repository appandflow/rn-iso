# Stim 1.0.0-rc.10 - faster iOS reuse and clearer runtime insight

## New

- Owned iOS simulators can be parked when a worktree is removed and adopted by
  a later matching workspace. Adoption resets app data, privacy grants,
  keychain state, and other user apps; ownership and cleanup remain fail-closed
  across crashes and concurrent garbage collection. `status` and `gc` expose
  the bounded pool, whose machine default is three simulators
  ([9136251](https://github.com/appandflow/stim/commit/9136251)).
- `stim stats` aggregates build timing and cache effectiveness without changing
  the build lifecycle
  ([4d0cabb](https://github.com/appandflow/stim/commit/4d0cabb)).
- iOS runs can select an installed simulator with `--device-type` and
  `--runtime`; Android runs can select an installed image with `--system-image`
  ([c29c6bd](https://github.com/appandflow/stim/commit/c29c6bd)).

## Fixes

- iOS fingerprints are computed while the simulator boots, and a simulator
  booted by the current run is not redundantly listed again
  ([9dbba71](https://github.com/appandflow/stim/commit/9dbba71),
  [e66bde6](https://github.com/appandflow/stim/commit/e66bde6)).
- Long native builds emit phase-named heartbeats sized from the project's last
  cold build instead of a fixed interval
  ([91a1d6e](https://github.com/appandflow/stim/commit/91a1d6e)).
- Worktree, server, device, and platform-run output uses one consistent phase
  vocabulary
  ([e759551](https://github.com/appandflow/stim/commit/e759551),
  [1daa954](https://github.com/appandflow/stim/commit/1daa954),
  [b91ca0a](https://github.com/appandflow/stim/commit/b91ca0a)).
- iOS simulator log collection anchors its process predicate to the installed
  app executable path, avoiding matches from unrelated processes
  ([b3915e0](https://github.com/appandflow/stim/commit/b3915e0)).
- Workspace overrides move `uuid`, `serialize-javascript`, and `qs` to patched
  dependency versions
  ([029854b](https://github.com/appandflow/stim/commit/029854b)).

## Docs

- Added the simulator-pool and aggregate-statistics designs, and documented the
  stacked pull-request workflow used for dependent changes
  ([d8de9c8](https://github.com/appandflow/stim/commit/d8de9c8),
  [7ebed3e](https://github.com/appandflow/stim/commit/7ebed3e),
  [d017f3c](https://github.com/appandflow/stim/commit/d017f3c)).

## Migration notes

- No command migration is required. Projects that require a completely fresh
  simulator system image for every worktree can set `pool.iosParkedMax` or
  `STIM_POOL_IOS_PARKED_MAX` to `0`.
