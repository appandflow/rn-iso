The quickest path from an existing React Native or Expo app to a working agent
loop, and from there to fast parallel builds. Steps 1 and 2 change nothing in
your repo; step 3 is the ten-minute integration that makes a second workspace
fast.

## 1. Run it — nothing to install

`rn-iso` runs via `npx` from the project directory. The whole loop is four
commands:

```bash
cd your-app
npx rn-iso start             # dev server on a reserved port, under a supervisor
npx rn-iso ios               # owned simulator booted, app built (or cache-installed), launched
npx rn-iso logs --errors     # no output + exit 0 = nothing is broken
npx rn-iso stop              # supervisor down, sim shut down, port freed
```

(`npx rn-iso android` is the same over an owned emulator.) That is already a
complete integration: the workspace gets its own Metro port, its own
simulator, structured logs under `.rn-iso/logs`, and a native-fingerprint
build cache shared across worktrees. The one write it makes to your repo is
adding `.rn-iso/` to `.gitignore` — commit that line.

## 2. Teach your agent

Install the bundled skills with the skills CLI, straight from GitHub:

```bash
npx skills add appandflow/rn-iso
```

That installs `rn-iso` (how to drive the CLI: the lifecycle, the ownership
model, the destructive-command rules) and `rn-iso-init` (how to apply `doctor`
findings). Then point the agent at it — one line in your `CLAUDE.md` /
`AGENTS.md`:

```markdown
Use rn-iso to run and verify the app: `npx rn-iso start`, then `npx rn-iso ios`
(or `android`), then `npx rn-iso logs --errors` — empty output means healthy.
```

Everything version-specific the agent needs at runtime comes from
`npx rn-iso guide <topic>`, generated by the installed binary so it cannot
drift from the CLI's behaviour.

## 3. Make the second workspace fast (~10 minutes)

Out of the box, every new worktree pays a cold Metro transform pass and a full
native build. `npx rn-iso doctor` reports what your repo is missing (read-only,
always exit 0); these are the usual two findings.

**A shared Metro transform cache** — one store for every worktree on the
machine, instead of Metro's per-project default that starts each checkout cold:

```bash
npm i -D @rn-iso/metro
```

```js
// metro.config.js
const { sharedCacheStores } = require('@rn-iso/metro');

const config = getDefaultConfig(__dirname);
config.cacheStores = sharedCacheStores('your-app');
module.exports = config;
```

**Expo only: a local build cache provider** — a JS-only change costs a
simulator install instead of a native compile, in every worktree on the same
commit. Which config key depends on the SDK, and the wrong one is a silent
no-op:

```bash
npm i -D @rn-iso/expo-build-cache
```

```jsonc
// app.json — SDK 54+
{ "expo": { "buildCacheProvider": { "plugin": "@rn-iso/expo-build-cache" } } }

// SDK 53 reads only the experiments key and ignores the top-level one
{ "expo": { "experiments": { "buildCacheProvider": { "plugin": "@rn-iso/expo-build-cache" } } } }
```

If cache hits never happen, add a `.fingerprintignore` for files that change
without changing the build — `ios/Podfile.lock` is the usual culprit (pod
checksums can embed absolute paths, so the fingerprint differs per machine).

Bare RN projects need nothing for the build side: `rn-iso ios` / `android`
fingerprint and cache builds on their own.

## 4. Parallel agents

Each worktree is its own project — its own reserved port, its own owned
simulator — so two agents build the same app side by side without fighting:

```bash
npx rn-iso worktree create fix-login   # carries gitignored files (.env etc.), prints the path
cd <printed path> && npm install       # or create with --carry-ignored to clone node_modules
npx rn-iso start && npx rn-iso ios     # a different port and sim than the main checkout
# ...work...
npx rn-iso worktree remove             # tears down the sim, frees the port, removes the tree
```

`npx rn-iso status` shows every workspace on the machine. `npx rn-iso gc`
reports anything left behind (and `gc --delete` reclaims it — the only
machine-wide destructive command there is).
